# 08 知识导图

本模块是全库的**提纲导图**：把 00–07 模块的全部正文笔记（目前 96 篇，不含各模块 README 与 CLAUDE.md）压缩成「模块 → 主题分组 → 笔记 → 核心要点」一张图，用来一眼看清全局、按层回忆复习。

它不产出新知识，只给已有笔记搭骨架；细节、论证与证据等级一律以原笔记为准。

**在线打开**：[网页导图](https://woniuguaniu.github.io/ai-knowledge-base/08_%E7%9F%A5%E8%AF%86%E5%AF%BC%E5%9B%BE/%E7%9F%A5%E8%AF%86%E5%BA%93%E5%AF%BC%E5%9B%BE.htm)。在 GitHub 仓库里点开 `知识库导图.htm` 只会显示网页源代码，要看导图请用这个地址；`.xmind` 要下载后用 Xmind 打开。

> 当前进度：**已收录全部 8 个模块、96 篇正文笔记、481 条要点**（2026-11-04）。00_核心概念由主会话逐篇精读；01–07 由子 agent 分批精读，依据表里的原话片段已逐一回查原文。

## 文件说明

| 文件 | 是什么 | 怎么打开 |
|---|---|---|
| [知识库导图.md](知识库导图.md) | 底稿，**唯一需要手工维护的源文件** | 任意编辑器；在 Quartz 站上显示为文字版大纲 |
| [知识库导图.htm](知识库导图.htm) | 网页导图（由开源工具 [markmap](https://markmap.js.org/) 生成，单文件、断网可用） | 本地双击用浏览器打开；在线看用上面的地址 |
| [知识库导图.xmind](知识库导图.xmind) | XMind 版 | 用 Xmind 打开，可再编辑、导出图片或 PDF |

网页和 XMind 都由 `_scripts/build_mindmap.py` 从底稿生成。**不要手工改这两个文件**——下次生成会被覆盖；要改就改底稿，再重新生成。

网页版用 `.htm` 而不是 `.html` 扩展名：Quartz 发布网站时会去掉资源文件的 `.html` 扩展名（见 Quartz 源码 `slugifyFilePath`），线上就变成一个无扩展名、还和底稿页面同名的文件；`.htm` 不受这个规则影响。

## 怎么用来复习

- 打开时只展开到笔记标题。先看标题，自己回想这篇讲了哪几点，再点开核对。
- 点笔记名会在新标签页打开线上网站的原文。还没推送到 GitHub 的笔记，要推送后才能打开。
- 网页里可以拖动、滚轮缩放；点节点旁的圆点展开或收起。

## 导图结构与提炼规则

**层级**：知识库 → 模块（一句话定位 + 篇数）→ 主题分组 → 笔记 → 核心要点。

**分组**：

- 优先沿用该模块 README 里已有的分类；02_提示词工程沿用它自己的编号体系与学习路线。
- 没有现成分类、且超过 8 篇的模块，按主题分 3–6 组，每组不超过 8 篇。
- 8 篇及以下、又没有现成分类的模块不分组，笔记直接挂在模块下。
- 现成分类里大多数组只有 1 篇时也不分组（例如 00_核心概念：8 篇分了 7 组），按模块 README 的推荐阅读顺序排列。
- 现成分类漏掉的笔记，归入主题最接近的组；放不进去的单独成组（例如 05 的「学习路线与证据规范」）。有独立索引的子项目单独成组（例如 05 的「GitHub 概念扫盲」）。

**要点**（每篇笔记下的叶子节点）：

- 每篇 3–5 条；内容很少的笔记可以 2 条，篇幅特别长的最多 6 条。
- 每条尽量控制在 20 字以内（按显示宽度算：汉字算 1，英文字母、数字、半角符号算 0.5）。
- 写**结论、流程或对比**，例如「预训练 → SFT → RLHF/DPO」；不写「介绍了 XX」「XX 很重要」这类空话。
- 只用该笔记原文里有的内容，不补充笔记以外的知识。
- 原文标了「经验」「待核验」「类比」的结论，要点里保留这个标记，不把它升级成定论。

**其他约定**：

- 每篇笔记在导图里**只出现一次**。底稿里写相对路径链接；生成网页和 XMind 时自动换成线上网址。
- 每篇笔记节点带一个「提炼记录」注释（提炼日期 + 原文内容指纹），用来发现「导图做完后原文又改过」的笔记。
- 导图末尾固定有一个「来源与局限性」分支，写明要点是压缩版、以原文为准，以及最后更新日期。

## 底稿格式

```markdown
## 00 核心概念｜AI/ML 基础理论（8 篇）

### 主题分组名（不需要分组的模块省略这一层）

- [笔记标题](../00_核心概念/笔记文件名.md) <!-- markmap: fold --> <!-- 提炼 2026-11-04 #1a2b3c4d -->
  - 要点一
  - 要点二
```

- `<!-- markmap: fold -->`：让这个节点默认折叠，也就是默认看不到要点。
- `<!-- 提炼 日期 #指纹 -->`：由脚本的 `stamp` 命令写入，不要手填。

## 怎么更新

```bash
python3 _scripts/build_mindmap.py check            # 检查：漏收、重复、断链、要点数量与长度、提炼后原文又改过的笔记
python3 _scripts/build_mindmap.py stamp 笔记路径…   # 改完某篇的要点后，刷新它的提炼记录
python3 _scripts/build_mindmap.py build            # 先检查，再重新生成 HTML 与 XMind
```

新增或修改笔记后：先跑 `check` → 按上面的提炼规则在底稿里补写或修改对应要点 → `stamp` 这几篇 → `build`。这套流程也写进了根目录 `CLAUDE.md` 的「知识导图维护」一节，后续会话改笔记时会照做。

`check` 的判定：

- **算失败**（退出码 1，`build` 会拒绝生成）：已收录的模块里漏了笔记、同一篇出现两次、链接指向不存在的文件、某篇要点少于 2 条或多于 6 条、底稿里出现既不是标题也不是列表项的行（markmap 会把它画出来、XMind 不会，两个成品就对不上了）。
- **只提醒**：整个模块还没收录（铺开阶段的正常状态）、单条要点超过 25 字、提炼后原文又改过、缺提炼记录。

## 验收标准

每次大改后都要满足：

1. `check` 不报失败。
2. `python3 _scripts/kb_check.py` 不新增问题。
3. 准确性抽查：每个模块抽 2 篇，要点逐条对照原文。
4. 网页不依赖外部 CDN，断网也能打开；默认折叠到笔记标题。
5. XMind 解包后的主题数与底稿节点数一致，并用 Xmind 实际打开确认。
