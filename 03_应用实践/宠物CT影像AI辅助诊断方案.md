# 宠物 CT 影像 AI 辅助诊断系统方案

> **定位：待验证的研究原型方案，不是已验证的临床产品或自动筛查上线方案。** 2026-09-30 修订验证设计、模型适用范围和安全边界；没有访问病例、训练模型或完成诊疗验证。

## Context

原讨论的场景假设：约 4000 份猫狗 CT（DICOM）及诊断记录，病种分散，开发者有编程经验但没有 ML 经验，标注人力有限。这些数据数量与质量未经本笔记核验。将“3 个月上线自动筛查”调整为“探索是否值得继续的离线研究原型”，后续临床使用另设验证与审批阶段。

## 核心挑战

- 总份数不等于独立患者数；重复检查、标签质量和病种分布需要先审计，不能单靠平均每类样本量断言可训练或不可训练
- 没有 ML 经验 → 需要尽量降低模型训练门槛
- 时间预算不能替代安全与证据门槛；允许原型停止、缩小任务或推迟上线

## 推荐方案：两阶段混合架构

### 第一阶段（时间为计划）：比较多模态与 RAG 的离线可行性

**核心思路**：不训练模型，用 GPT-4o / Claude 的视觉能力 + 历史病例检索做辅助诊断。

```
DICOM 上传
    ↓
① 预处理：保留原始 DICOM 体数据与元数据；经审定规则导出研究用切片
    ↓
② 检索相似病例：仅从开发/参考库检索，不包含验收患者及其重复检查
    ↓
③ 多模态大模型分析：
   输入 = CT 切片图 + 相似病例的诊断记录 + 结构化提示词
   输出 = 待复核的影像描述 + 证据引用 + 不确定性/拒答标记
    ↓
④ 兽医审核界面：展示 AI 建议 + 相似病例对比
```

**技术栈**：
- DICOM 处理：`pydicom` + `SimpleITK`
- 图像标准化：保留体素间距、方向、HU 等；PNG 只是有损的显示视图，不能替代完整序列。选片遗漏与三维空间信息损失必须单独评估
- 相似病例检索：先建文本/结构化元数据基线，再比较候选图像编码器。BiomedCLIP 等需验证跨物种、跨模态适用性；**RAD-DINO 官方模型卡描述的是胸部 X 光研究编码器，不是已验证的猫狗 CT 编码器，且不面向临床使用**
- 模型候选：以数据使用条款、允许的研究用途、输入能力和本地评估选择；不凭通用多模态排名认定能诊断宠物 CT。实际调用前核对具体版本与供应商限制
- 后端：FastAPI
- 前端：React + DICOM 查看器（cornerstone.js）
- 部署：阿里云/AWS

**提示词设计（核心）**：
```
你是离线影像研究助手，不作独立诊断。只记录可核对的观察与待兽医复核的问题。

患者信息：
- 物种：{species}，品种：{breed}，年龄：{age}，体重：{weight}
- 扫描部位：{body_part}
- 临床症状：{symptoms}

以下是该患者的 CT 切片图像。

参考病例（与本例最相似的历史诊断）：
{similar_cases_with_diagnosis}

请分析：
1. 是否有疑似异常？区分可见观察与推测；没有标尺或原始数据时不得编造尺寸、HU
2. 有哪些待兽医复核的可能解释？逐条指出影像或参考材料依据；资料不足则明确拒绝推断
3. 哪些信息或完整序列需要补充？
4. 与参考病例的异同点

注意：你的分析仅作为辅助参考，最终诊断由兽医做出。
```

这段提示词不是医疗安全控制。研究界面要保留原图、引用、模型版本和拒答状态；不能把模型自报“90%”当作校准概率。若需要概率，必须在独立数据上评估校准，并按风险预设阈值。

### 第二阶段（Month 3+）：专用检测模型，提升特定病种精度

只有数据审计和离线评估支持继续时，才考虑针对明确任务训练或微调专用模型；通用模型失败不自动意味着训练专用模型就能成功。

**技术选型**：
- 框架：MONAI（NVIDIA 医学影像专用框架，基于 PyTorch，文档好）；PyTorch 与 OpenCV 的关系、四阶段实战例子参见 [../00_核心概念/计算机视觉与深度学习框架.md](../00_核心概念/计算机视觉与深度学习框架.md)
- 预训练模型：用 MONAI 提供的预训练权重做迁移学习
- 任务类型：分类（正常/异常）+ 检测（标注病灶位置）
- 训练平台：AutoDL / 阿里云 PAI（按小时租 GPU，不用自建）

**数据准备**：
- 先定义任务与标注规范，由有资格的兽医影像人员标注；重要标签设置独立复核与分歧仲裁，不能用模型生成结果充当真值
- 标注工具：3D Slicer（免费，支持 DICOM，支持体积标注）
- 样本量：按患病率、期望灵敏度、置信区间与病种亚组设计；不把“每类 200 份”当作普遍充分条件

**与第一阶段的融合**：
- 专用模型输出也须经验证与兽医审核，不因“高置信度”跳过复核
- 罕见病、超出验证范围、图像质量差或模型冲突时，明确转专家，不由 RAG 或通用模型“兜底诊断”
- 合并展示时保留证据、不一致意见和模型版本，研究输出不直接驱动治疗

## 研究原型里程碑（估计，不承诺 3 个月上线）

| 时间 | 目标 | 交付物 |
|------|------|--------|
| Week 1-2 | 先决条件 | 权利与脱敏审计、患者去重、标签审计、独立数据划分 |
| Week 3-4 | 基线与检索 | 参考库、固定验收问题、文本检索与图像候选基线 |
| Week 5-6 | 离线原型 | 输入序列 → 待复核描述，保留证据与失败日志 |
| Week 7-8 | 研究界面 | 原图查看、出处、拒答、版本和访问控制 |
| Week 9-10 | 独立评估 | 冻结方案后评估，不边看验收答案边调提示词 |
| Week 11-12 | 决策评审 | 继续/缩小范围/停止；需要临床研究时另行制定方案 |

## 关键风险与应对

| 风险 | 应对 |
|------|------|
| 大模型看不懂宠物 CT | 小样本用于发现明显不可行因素；失败可停止或缩小任务，不自动切换路线 |
| 数据病种分布不均 | 分病种报告表现；稀缺病种转专家，不把检索当安全兜底 |
| 单人标注速度慢 | 第一阶段不需要标注（用已有诊断记录）；第二阶段只标注高频病种 |
| 数据与医疗合规 | 调用外部 API 前确认权利、脱敏、供应商条款和适用法规；免责声明不替代这些步骤 |

## 验证方式

1. **探索不等于验收**：约 20 个病例可用于管线冒烟和发现明显问题，不足以证明临床有效。单位应是患者/检查，而非把同一检查的切片当独立样本。
2. **患者级隔离**：开发集、调参验证集、最终测试集隔离同一动物的所有重复检查；测试病例及其报告不能进入检索库。可行时增加时间或机构外部验证。
3. **先定义真值与指标**：由兽医专家制定标签标准并盲法复核；按具体任务报告分病种灵敏度、特异度、严重漏诊、误报、拒答率和置信区间。Top3 命中率仅作补充。
4. **避免调参污染**：仅在开发/验证数据上选择模型、提示、切片与阈值，冻结后使用测试集；多次据测试集调整后需另设独立验收数据。
5. **研究门槛先约定**：由领域专家按风险制定目标与停止规则，不使用通用的“70% 可行、50% 换路线”。出现危急病例漏检、引用泄漏或域外病例自信诊断时，停止相应用途并复核。
6. **上线单独评估**：原型通过只支持下一步研究；真实使用还需评估人机协同、自动化偏见、监测、回滚以及适用法规，不能直接开通自动筛查。

## 需要你现在做的第一步

1. 与兽医影像专家明确一个低风险研究任务、禁用范围和真值标准。
2. 核查数据授权、患者去重与脱敏；DICOM 标签及图像烧录文字都要检查，未经批准不上传外部服务。
3. 保留原始序列，按预先制定的规则准备少量研究病例，比较简单基线与候选模型。
4. 保存错误和不确定性，决定是否值得扩大研究；不承诺 1–2 天即可证明可用。
