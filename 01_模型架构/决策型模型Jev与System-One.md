## 1. 背景与问题

过去几年所有人都在把大模型往"更会聊天、更会推理"的方向推。Jev 的作者 Diogo Almeida 在 OpenAI 参与过 RLHF、InstructGPT、ChatGPT 和 GPT-4 的工作，他离开后问了一个反向的问题：**聊天模型早就超过人类了，为什么自动化还是没发生？** 他的答案是：软件需要的不是一段话，而是一个能直接拿来分支的判断。于是他花两年做了一类新模型，不生成文字，只输出带概率的决策。

这个模型 2026 年 9 月 15 日发布后迅速走红，Hacker News 主帖近两千分五百多条评论，国内论坛一周内冒出五六个讨论帖。讨论里高频出现一堆新词：System One、RLCD、并行采样、校准、类型安全、零幻觉、Choice / Score / Noul。同时又有一批人问"它能不能干 X"，其中最热闹的是"能不能做自动驾驶的决策层"。

本文回答两个问题：Jev 到底是什么、不是什么；以及拿"自动驾驶"这个极端案例，演示怎么判断一个新模型适不适合某个场景。本文不讲 API 调用代码，官方文档比这里写得全。

## 2. 核心结论

| 问题 | 结论 |
|---|---|
| Jev 是什么 | 一个只输出类型化决策和概率、不生成文字的模型。官方叫它 System One 模型，社区叫它"带通用常识的零样本分类器" |
| 和普通大模型最大的区别 | 普通大模型逐字生成，Jev 一次并行算出所有问题的概率分布。快两个数量级，便宜两个数量级，但只能回答你预先定义好答案空间的问题 |
| "零幻觉"是真的吗 | 只在"不会输出定义之外的东西"这个意义上是真的。它照样会选错，作者自己承认"也可能自信地答错" |
| 能力档次 | 在 TypeSafe 自建评测上和 GPT-5.6 Terra、Claude Sonnet 5 同档，比 Opus 5 和 GPT-5.6 Sol 低五六个点。数字密集型任务差距最大 |
| 正确用法 | 高频、低复杂度、答案离散、需要概率的判断：分类、路由、打分、抽取、护栏。官方比喻是"聪明的 if 语句" |
| 能不能做自动驾驶决策层 | 不能做感知，不能跑控制频率，不能做核心决策。能在"绕还是越、左还是右"这类每秒几次的战术层做建议，前提是代码握否决权 |
| 最大风险 | 把"格式不会错"误读成"判断不会错"；把中文输入的结果当成英文同等可靠；把多次询问当成独立投票 |
| 一句话记忆 | 感知归视觉，控制归控制器，安全归规则，Jev 只在中间做判断，代码随时否决 |

## 3. Jev 是什么：与普通大模型的本质区别

### 3.1 输出方式：并行给出类型化决策，而不是逐字生成

**一句话理解**：普通大模型是"打字机"，一个字一个字往外蹦，每个字都要等前一个字出来才能算。Jev 是"投票器"，你给它一组选项，它一次算出每个选项的概率。

**生活类比**：问一个医生"这个病人该转哪个科"。让他写一份会诊意见要十分钟，让他在分诊单上勾一个科室并标注把握程度只要三秒。Jev 做的是后者，而且可以同时勾十张分诊单。

**技术上的差别**：

| 维度 | 普通大模型 | Jev |
|---|---|---|
| 生成方式 | 自回归，逐 token 生成，每步依赖上一步 | 并行采样，一次前向传播输出所有预设槽位的概率 |
| 输出类型 | 任意字符串，可以是回答、代码、拒绝、幻觉 | 只能是预先定义的类型：选项、等级、是否 |
| 类型安全 | 靠 JSON 模式"尽量"合规，仍可能截断、漏字段、编造选项 | 架构层面保证，不存在"写"这个动作，格式错误在数学上不可能 |
| 附带信息 | 无。问它"你有多大把握"，答案不可靠 | 每个答案自带概率分布和置信度 |
| 多问题 | 问十个问题要生成十段话，互相干扰 | 十个问题并行独立评估，加问题几乎不增加耗时 |
| 速度 | 数秒到数百秒 | 70 到 500 毫秒 |

**和 JSON 模式的区别**：OpenAI 的 json_schema 严格模式也能保证格式合规，但它的原理是在逐字生成时用语法约束"不让模型写出不合规的字"，本质还是在写字，还是要消耗输出 token，还是可能触发拒绝或空输出。Jev 根本不写字，输出免费。

**为什么能这么快**：普通大模型每出一个 token 都要把激活参数从显存完整读一遍，长回答等于读几百遍。Jev 只读一遍，所有答案同时出来。这也是它"输出 token 免费"的物理基础。

### 3.2 三种原语：Choice、Score、Noul

Jev 只回答三种问题，官方叫它们"AI 原语"，意思是像编程语言里的基本类型一样可组合。

| 原语 | 问什么 | 返回什么 | 例子 |
|---|---|---|---|
| Choice | 从一组选项里选一个 | 选中项、每个选项的概率、置信度 | "这张工单该转哪个部门"，返回 billing 0.08、technical 0.85、sales 0.07，置信度 0.82 |
| Score | 按你定义的等级打分 | 分数、每个等级的概率、置信度 | "客户有多生气"，0 平静、1 不满、2 暴怒，返回 1.4 |
| Noul | 一句陈述是否为真 | 0 到 1 的概率 | "客户是否要求退款"，返回 0.95 |

**使用方式**：把要判断的材料放进 state 字段，可以是一段文本，也可以是 JSON 对象；把问题放进 questions，每个问题写清指令和选项标准。一次请求可以混合三种问题，全部并行评估。Choice 最多 255 个选项。

**官方强调的设计原则**："原子问题，代码组合"。不要问"这个创业项目值不值得投"，要分别问市场规模、技术可行性、差异化各打几分，然后在代码里用你自己的权重加总。需求变了改系数，不用改提示词。

### 3.3 训练方法：RLHF、RLVR、RLCD 三条路线

**一句话理解**：预训练出来的底座模型是"博学但不听话"的，后训练决定它变成什么。目前有三条路。

| 路线 | 全称 | 优化目标 | 产物 | 副作用 |
|---|---|---|---|---|
| RLHF | 人类反馈强化学习 | 人类评分员更喜欢的回答 | ChatGPT、Claude 这类聊天模型 | 迎合、过度自信、模式坍缩 |
| RLVR | 可验证奖励强化学习 | 能自动判对错的任务，如数学、代码 | o1、DeepSeek R1 这类推理模型 | 慢、贵 |
| RLCD | 校准决策强化学习 | 输出的概率和真实正确率一致 | Jev | 不能生成文字 |

**RLHF 的问题，用作者自己的话说**：RLHF 教模型说人爱听的话。这个目标对聊天很好，但会奖励谄媚和"听起来很自信的幻觉"。偏好优化还会造成"模式坍缩"的轻度版本，模型学会偏爱某种风格，其他可能的输出概率被压低。一个回答能让人满意，不代表它可靠到能无人值守地自动执行。

**RLCD 的目标**：不生成文字，只返回决策和概率，概率越高对应正确率越高。RLHF 和 RLVR 的对比见 [模型训练技术速查 § 3](../00_核心概念/模型训练技术速查.md#3-rlhf人类反馈强化学习)；RLVR 路线的代表 DeepSeek R1 见 [DeepSeek](DeepSeek.md)。

### 3.4 校准：说八成把握就真有八成对

**一句话理解**：一个校准好的模型，在它标 0.8 的一百个答案里，真的有八十个是对的。

**生活类比**：天气预报说"降水概率 30%"，你回看一整年，所有说 30% 的日子里确实大约三成下了雨，这个预报员就是校准的。一个总说"肯定下雨"结果一半没下的预报员，准确率可能不差，但你没法根据他的话决定带不带伞。

**为什么这对软件重要**：有了校准的概率，代码就能设阈值。官方推荐的三段式：高置信度自动执行，中置信度谨慎处理或让用户确认，低置信度转人工或转推理模型。阈值随风险浮动，查余额可以 0.6 就放行，批准转账要 0.9 以上。

**两个必须知道的限制**：

1. 校准是**群体统计**，不保证单个答案正确。官方文档原话。
2. 到本文整理时，**没有任何第三方独立验证过** Jev 的校准曲线。这是外媒评测公认的最大空白。

**和本知识库"校准 Judge"的区别**：[Eval 测评体系 § 2.3](../06_Agent工程/Eval测评体系.md#23-llm-as-judge用-ai-当裁判) 里说的"用两百条人工金标校准 Judge"，是校对裁判模型可不可信。这里说的是模型输出的概率数字本身是否可信。两者都是"可信度"问题，层次不同。

### 3.5 "零幻觉"的真实含义

这是 Jev 营销里最容易被误读的一句话，值得单独拆开。

| 说法 | 真假 | 依据 |
|---|---|---|
| Jev 不会输出定义之外的选项 | 真 | 架构保证，官方称"格式匹配有保证" |
| Jev 不会出类型错误、不会编造工具名 | 真 | 同上 |
| 官方图表里的"0% 幻觉率"是实测的 | 假 | 博客注脚原话："我们的数字不是实证的，格式匹配有保证，所以填了 0" |
| Jev 不会答错 | 假 | 作者在 HN 回帖："也可能自信地答错，未来更聪明的模型也一样" |
| Jev 每次给同样输入答案一样 | 基本真 | 官方说"极其一致，相似输入给相似输出"。但这恰恰意味着重复问不能当独立投票 |

**正确的读法**：零幻觉等于零格式错误，不等于零判断错误。给它三个选项 Billing、Technical、Sales，它绝不会答 Legal，但完全可能在该选 Technical 时选了 Billing。

## 4. 官方承认的九条缺陷

TypeSafe 发布了一个叫"jaggedness"的页面，逐条列出 jev-1.13 做不好的事。这份清单比外界任何批评都实在，读 Jev 之前先读它。

| 序号 | 缺陷 | 官方描述 | 官方建议 |
|---|---|---|---|
| 1 | 字面理解 | 回答你写的问题，不是你想问的。否定词、限定词、隐含条件都按字面读 | 把确切条件写进指令，边界情况写进标准。发现自己在解释"我其实想问的是"，那段解释就是缺失的半句指令 |
| 2 | 数学与计数 | "Jev 不是计算器"。数字符、数词频、数列表项都不可靠，越长越错。它是"认答案的形状"而不是在数 | 计数放代码里。要数满足条件的项，就逐项问一个 Noul 再自己加总 |
| 3 | 日期比较 | 把日期当文本读。比先后、算间隔、判断是否在窗口内都不可靠 | 让它抽取年月日各部分，比较放代码里 |
| 4 | 多跳推理 | 双重否定、属性的属性、需要多步推导的问题准确率下降 | 减少跳数，直接指名 state 里的相关字段 |
| 5 | 大 state 稀释 | 无关内容越多准确率越低，官方称之为 context rot | 先在代码里过滤，只发问题需要的字段 |
| 6 | 对抗内容 | 不把 state 当敌意数据。注入的指令、误导性措辞、为自己辩护的文本都能改变答案 | 标准写精确，上线前测边界 |
| 7 | 指令与标准矛盾 | 指令说一套、选项标准说另一套时会混乱。true 映射到"否"这种反向设计表现更差 | 两者对齐，用普通人一读就懂的话 |
| 8 | 结构不变量不保证 | 同一件事用 Noul 问得 0.22，用 Choice 问 yes 得 0.01。问"是否退款"得 0.72，问"是否不退款"得 0.47，加起来 1.19 | 不要指望不同问法之间自洽，不要把 Noul 上调好的阈值搬到 Choice 上 |
| 9 | 不能生成 | 强行串 Choice 生成文本"效果差且很慢" | 抽取任务先用正则或生成模型列候选，再让 Jev 选 |

**附带一条**：Score 的等级"数值校准弱"，不要用打分的期望值反推精确数字，等级之间不能插值。想用 Score 输出连续控制量不靠谱。

**四件官方明确让你别做的事**：问代码能精确算的东西；把几个判断藏进一个问题；System Two 任务，也就是多层间接推理；给的 state 比问题需要的多。

## 5. 评测数据怎么读

**官方评测**：TypeSafe 自建了四个业务流程，共 711 个案例，每个模型跑同一套代码流程，只把里面的判断题交给模型。

| 模型 | 一致率 | 每案例成本，美元 | 延迟，秒 |
|---|---|---|---|
| Jev | 67.8% | 0.0004 | 0.4 |
| GPT-5.6 Terra | 67.9% | 0.0304 | 10.1 |
| Claude Sonnet 5 | 67.8% | 约 Jev 的 293 倍 | 约 Jev 的 195 倍 |
| Claude Opus 5 | 73.1% | 0.1761 | 37.8 |
| GPT-5.6 Sol | 74.1% | 0.0836 | 23.3 |

分流程看：客户服务 76.0%，接近 Sol 且高于 Opus；发票处理 61.8%，对 Sol 的 79.1%，差距最大，这正是数字密集型任务，和第 4 节的缺陷 2 吻合。

**三个必须知道的注脚**：

1. 表里的"一致率"不是对照真实标签，而是和 GPT-6 Astra 与 Claude Fable 5.1 两个模型平均答案的一致程度。所以这两个模型本身不在表里。
2. 四个流程由 TypeSafe 自己设计、自己跑，没有第三方复现。官方承认"可能存在偏差"。
3. 首页那句"快 193.6 倍、便宜 444.6 倍"来自这套评测，官方说"预期是真实收益的高端"。

**为什么没有公开基准分数**：Almeida 在播客里明确说他"极度反对公开基准测试"，理由是公开基准极易被刷，"以前每个实验室都有一个团队专门收集长得像 MMLU 的数据"。所以你找不到 Jev 的 MMLU 或任何标准榜单成绩。

**已有的独立小测试**：一个事实核查任务准确率 96.3%；一个代码缺陷查找任务，Jev 找到七个里的六个，Claude Fable 5.1 全找到，Jev 三次运行漏的是同一个。后者说明它的错误是**系统性的**，不是随机的。

## 6. 正确用法：聪明的 if 语句

**官方定位**：AI 驱动的工作流里的"模糊决策规则"。手写逻辑太脆弱的地方，用 Jev 做分类、路由、打分、抽取、分支，周围的代码限制它的自由度。

**官方四种模式**：

| 模式 | 做什么 | 好处 |
|---|---|---|
| 推测性扇出 | 一次请求塞进很多问题，包括可能用不上的，代码再决定哪些有用 | 输出免费，多问不花钱；官方实测 13 个问题合并成一次比分开问便宜 12 倍、快 10 倍 |
| 置信度门控路由 | 答案告诉你"是什么"，置信度告诉你"该不该动" | 高置信自动，低置信转人工 |
| 复合打分 | 把复杂判断拆成多个原子分数，代码里加权 | 权重可控，改需求不改提示词 |
| 意图路由 | 先分类用户意图，再分发给确定性逻辑、专家大模型或人 | 一次 Jev 调用决定要不要调大模型，省下的是大模型的钱 |

**社区 48 小时内做出来的东西**，按类别归纳：

| 类别 | 例子 |
|---|---|
| 大模型的前置和后置 | 模型路由、记忆检索路由、上下文即时压缩、输出护栏、AI 文本检测、引用核对 |
| 开发流程 | PR 审查打分、代码质量打分、QA 测试判定、堡垒机实时判断 shell 命令是否危险 |
| 实时交互 | 浏览器自动化、iOS 模拟器控制、Computer Use 动作选择、实时会议观察、自动补全候选排序 |
| 数据处理 | 简历初筛、层级分类、实体对齐、日期抽取、SQL 筛选 |
| 游戏和模拟 | 玩 Doom、玩我的世界、模拟器里开车、模拟器里飞无人机、每 300 毫秒做一次买卖决策的做市机器人 |

**一个中文社区里的好比喻**：Jev 像人的小脑或脊髓，负责"下意识"的快速反应；大模型像大脑皮层，负责想清楚要干什么。两者互补，"大模型决定要干什么，Jev 去执行每一步的判断"。

**工具调用场景的对应关系**：[Function Calling 与 MCP 工程指南](../06_Agent工程/Function%20Calling与MCP工程指南.md) 里让大模型自己选工具、自己填参数的做法，在 Jev 这里变成"Choice 选工具名、Noul 判断要不要调、参数从闭集里选"。官方 cookbook 有 function calling 示例。

## 7. 案例演练：Jev 能不能做自动驾驶的决策层

这一节用一个真实争论演示"怎么判断新模型适不适合某个场景"。争论发生在 2026 年 9 月 20 日的一个技术论坛帖，29 楼，22 人参与。

### 7.1 争论起点：一次模拟驾驶场景测试

发帖人让 GPT 写了一个请求体喂给 Jev。输入是一段 JSON，描述周围车辆：左前方小型乘用车距离 68 米时速 98，左后方小型乘用车距离 47 米时速 101 相对速度 9，右前方重型卡车距离 24 米时速 67，右后方小型乘用车距离 19 米时速 96。然后问了五个问题：

| 问题 | 类型 | Jev 的回答 |
|---|---|---|
| 当前最合理驾驶行为 | Choice，7 选项 | 向左变道 77%，减速跟车 17%，强力减速 4%，紧急制动 2%，向右变道、进入最小风险状态、保持车道均 0%。置信度 72% |
| 是否适合向左变道 | Noul | 81% 是 |
| 是否存在紧迫碰撞威胁 | Noul | 13% 是 |
| 场景是否存在明显异常或不确定性 | Noul | 11% 是 |
| 短时碰撞风险等级 | Score，0 到 4 | 2.76，概率集中在等级 3 |

两段耗时合计 411 毫秒。发帖人的结论：模型参数量不大，开源版会跟进，车上本地部署不难，做智驾决策层前景很大。

**先指出这个测试本身的三个问题**，都能从第 3、4 节直接推出：

1. **输入是中文**。官方说中日韩文准确率明显更低，所以这些百分比本身打了折扣。
2. **五个问题互不保证自洽**。"最合理行为是向左变道 77%"和"是否适合向左变道 81%"是两次独立计算，第 4 节缺陷 8 明说这类结构不变量不保证。生产系统得用代码检查它们是否矛盾。
3. **输入里的 JSON 是人手写的**。真实车上，把摄像头画面变成"左前方小型乘用车 68 米时速 98"的是感知模块，那才是整个系统最难的部分。Jev 只负责拿到干净 JSON 之后的那一小步。

### 7.2 自动驾驶架构演进：规则式、模块化、端到端、VLA

要判断 Jev 在车上的位置，先要知道车上现在是什么架构。

| 代际 | 做法 | 输出什么 | 现状 |
|---|---|---|---|
| 规则式 | 工程师手写 if else：前车距离小于多少就刹车 | 离散动作 | 场景覆盖有限，"L3 要是靠它早普及了" |
| 模块化流水线 | 四段：感知看清周围有什么，预测猜别人下一步，规划算自己的路线，控制转成方向盘和油门 | 规划层输出未来几秒的轨迹，一串连续坐标 | 传统主流，规划层混合规则和优化 |
| 端到端 | 一个神经网络从传感器直接到轨迹或控制指令，中间不拆模块 | 连续轨迹或控制量 | 特斯拉 FSD v12 起走这条路，国内厂商跟进 |
| VLA | 视觉、语言、动作模型。在视觉和动作之间加一层语言理解，用来吸收常识 | 连续轨迹，可附带语言解释 | 最早出自 Google 的机器人研究，NVIDIA 把它推到车上，2026 年多家车企采用 |
| 世界模型 | 能预测"下一秒世界会变成什么样"的模型 | 未来状态 | 被视为下一代路线 |

**三个关键词**：

- **定制输出头**：神经网络最后一层按任务专门设计。智驾的输出头直接吐出未来几秒的连续坐标序列，不是几个离散选项。
- **隐空间**：神经网络内部的中间表示。"从隐空间出轨迹"就是不经过语言，直接从内部表示算出路线。
- **感知不确定性**：传感器看不清、看不准的程度。真实系统会把这个不确定性带到下游，文本描述会把它抹掉。地上飘来一个看不清是小动物还是塑料袋的东西，这个 JSON 怎么写？

### 7.3 两派观点归位

论坛里两派的核心论点，按本文的框架归位：

| 立场 | 论点 | 本文的核对 |
|---|---|---|
| 看好 | 智驾场景恰好是输入大量文本、输出有限决策、延迟要求高 | 前半句错：输入是连续传感器流，不是文本。后半句对 |
| 看好 | 算力够到每秒判断百次，错一次不值一提 | 不成立。顺序调用上限每秒 7.4 次，流水线 21 次。而且见 7.4，更快也没用 |
| 看好 | 人开车本质也是短时间内大量判断 | 类比成立，但人的判断建立在视觉感知上，Jev 没有视觉 |
| 看好 | 现在决策层还有大量硬编码规则，常识覆盖不够 | 问题是真的，但行业解法是 VLA 把常识揉进端到端网络，不是外挂文本判断器 |
| 看好 | 单次错误率 1%，5 次独立判断多数表决压到千分之一 | 数学对，前提错。官方说模型"极其一致"，同一输入问 5 次错就一起错，不独立 |
| 看好 | 失误率低于现有智驾就能替换 | 标准对，但没有任何数据支持 Jev 在驾驶任务上的失误率 |
| 质疑 | 错一次是几条人命，所以现在都有兜底规则 | 对。见 7.4，解法是架构：模型提议，规则裁决 |
| 质疑 | 智驾模型本来就直接输出动作，用通用输出格式是开倒车 | 对。定制输出头出连续轨迹，Jev 出离散选项，信息量差一个层级 |
| 质疑 | 主流是 VLA，Jev 只能解决语言那一层，而智驾要语言干什么 | 前半对。后半有例外，语音指令意图、场景标注、数据挖掘都是语言层的活 |
| 质疑 | 输入丢了感知不确定性，输出丢了执行细节。"适合向左变道"是急打一把还是减速伺机插队？ | 整场争论最扎实的一楼，全部成立 |
| 质疑 | 连数数都是概率性的，不能用在高精度场景 | 官方缺陷页第 2 条直接确认 |
| 质疑 | 你宁愿信一个没吃过多少数据的通用模型，也不信吃了海量路况数据的专业模型？ | 对，而且是结构性的：官方不支持微调，想喂驾驶数据没有入口 |
| 质疑 | 判断题难度差异巨大，Jev 在稍复杂的题上打不过前沿模型 | 方向对。自家评测里 Jev 与 Terra 同档，比 Opus 5 和 Sol 低五六个点 |

### 7.4 决定性实证：把 Jev 放进无人机控制回路

社区有一个开源项目 jev-drone 恰好回答了这场争论。作者在 MuJoCo 物理仿真里让一架只带摄像头的四旋翼飞过五关障碍赛道，Jev 在回路里。它的分层设计值得整段记住：

| 频率 | 层 | 谁负责 |
|---|---|---|
| 500 Hz | 姿态与推力控制 | 代码，零 Jev |
| 50 Hz | 制导与安全反射 | 代码，永远拥有安全权，可以否决 Jev |
| 15 Hz | 摄像头转符号化场景：五个前向距离扇区、障碍物高度、目标方位 | 传统计算机视觉，零 Jev |
| 约 2.5 Hz | 战术判断：绕过去还是飞过去、哪边、目标是不是真丢了 | 100% Jev，仅作建议 |

作者原话：**"Jev 不是视觉模型。它吃 JSON 返回带概率的类型化答案。所以它不能做感知层，也不能跑在控制频率上。它能做的是回答代码很难用规则表达的小问题。"**

**结果分两面**：

| 指标 | 不用 Jev 的基线 | 用 Jev |
|---|---|---|
| 最远到达 | 17.7 米，三次都卡在第二关 | 77.5 米，全程通关 |
| 目标可见率 | 约 19% | 82% |
| 困在反射层的时间 | 65% 到 71% | 9% |
| 碰撞 | 0 | 0 |
| 延迟 | 无 | 中位 0.11 秒，65 秒飞行 80 次调用 |

基线每次卡在第二关，是因为"飞过去"这个动作它表达不出来，Jev 补上了这个动作。作者的诚实注脚：这是单次运行不是多种子平均；**在更简单的早期场地上，三种子对照 Jev 没有任何优势**，多余的机动反而损失了目标可见率。

**更激进的实验**：让 Jev 做唯一导航器，不带反射层和手写避障，用两个 Score 问题直接映射到转向量。结果"飞机稳定了，最好的几次零碰撞，但不能可靠飞完整个隧道，倾向于过度躲避撞墙"。作者标注为"部分结果，不是可用系统"。

**两条最有价值的教训**：

1. **反应时间预算**。以 9 米每秒飞行，感知 0.03 秒，Jev 0.118 秒，机体横移两米要 0.7 秒。模型只占回路的 13%，机体占 80%。作者说"把决策做得更快帮不上忙，把机体逼得更狠只会翻"。这直接回答了"每秒判断百次"的设想。
2. **state 里必须包含答案**。Jev 一开始从不选"爬升"，因为 state 只有五个水平方向的距离扇区，没有任何垂直信息，"飞过去"根本推不出来。加上障碍物顶边高度和自身爬升上限后，爬升概率变成 0.93。作者说"这是 state 设计的 bug，不是模型的错，是整个项目学到的最有用的一件事"。这和 7.3 里"输入丢了感知不确定性"是同一个问题的两面。

### 7.5 结论：Jev 在车上的位置

| 层 | 归谁 | Jev 能不能做 | 原因 |
|---|---|---|---|
| 感知 | 传统视觉或端到端网络 | 不能 | 只吃文本 |
| 控制 | 控制器 | 不能 | 需要 50 到 500 Hz，Jev 顺序上限 7 Hz |
| 安全兜底 | 硬规则 | 不能 | 会被对抗内容带偏，且判断错误率未知 |
| 核心规划 | 端到端或 VLA 的定制输出头 | 不能 | 输出离散选项，缺连续轨迹和执行细节 |
| 战术建议 | 可以是 Jev | 能，每秒几次 | 前提是代码握否决权，state 设计得当 |
| 语言层 | 可以是 Jev | 能 | 语音指令意图分类、路测数据打标、场景检索 |

**一句话**：感知归视觉，控制归控制器，安全归规则，Jev 只在中间做判断，代码随时否决。发帖人设想的"作为智驾的决策层"和这个位置差两层：他把感知的产物当输入喂给 Jev，而感知才是难点；他把 Jev 的选择当决策，而真实系统里那只是一个建议。

**关于那些"一小时重建特斯拉自动驾驶"的演示**：全部在模拟器里，外媒核实"没有一个在真实硬件、真实传感器噪声或安全关键失效模式下测试过"。它们证明的是"给一个动作列表和结构化状态，Jev 能在 15 分钟内做出局部合理的决策"，不是"Jev 能开车"。

## 8. 社区质疑与历史脉络

**这不是新概念**。BERT 九年前就能用不到 5 亿参数做分类和情感分析。有人一年前就用强化学习做过非自回归决策模型。发布 48 小时内出现了开源接口克隆和名为 CUA-S1 的仿制品，HN 上有人说"用 Qwen 3.5 2B 做后训练就能复现"，中文社区有人说"推出的一瞬间就失去了技术壁垒"。

**那新在哪**。多数人认可的新意是三件事的组合：校准训练 RLCD，并行采样器，以及把"决策原语"做成标准 API。有人拿 Cursor 类比：自动补全早就有，但 Cursor 把它做成了所有人一看就懂的产品形态。

**营销措辞的争议**。HN 上被点赞最多的批评针对措辞：给一个不能对话的模型冠以"前沿模型"，借了不该借的信用；"两年潜伏""不会幻觉""突破"这些词让一部分人第一反应是"像个骗局"。速度对比也不公平，70 毫秒对 329 秒，后者是带完整思维链的推理模型。

**一个值得记住的反向观点**：不止一位工程师指出，我们被万亿参数模型惯坏了，"一刀切用大模型"是前沿实验室让你多买 token 的营销，浪费电、时间和钱。Jev 的走红说明很多人早就怀疑生产管线里的大量调用是在"为没人读的文字付费"。

## 9. 常见误区

| 误区 | 为什么错 | 更好的做法 |
|---|---|---|
| 零幻觉等于不会错 | 只是不会出格式错，选错选项照样发生 | 自己做标签集测试，设保守阈值，保留人工升级路径 |
| 中文输入和英文一样可靠 | 官方明说中日韩文准确率明显更低 | 中文场景先自测，重点看置信度 |
| 多问几次投票能降错误率 | 模型极其一致，重复问不独立 | 换角度拆成不同的原子问题，而不是同一问题重复问 |
| 让它算数、比日期、数个数 | 官方缺陷页前三条 | 这些放代码里，模型只做语义判断 |
| 把整个系统状态都塞进 state | 无关内容稀释准确率 | 代码先过滤，只发问题需要的字段 |
| 不同问法的答案应该自洽 | 官方明说结构不变量不保证 | 一件事只用一种问法，阈值不跨类型搬 |
| 评测表里的准确率是真实准确率 | 是和两个大模型平均答案的一致率，且自测无复现 | 当作"能力档次参考"，不当作保证 |
| 能进控制回路就能做控制 | 无人机项目：能做每秒几次的战术建议，做唯一导航器是部分失败 | 感知、控制、安全留在代码，Jev 只做中间判断 |

## 11. 术语速查

| 术语 | 全称或来源 | 大白话 |
|---|---|---|
| System One 模型 | 出自卡尼曼《思考，快与慢》 | 快速直觉判断型模型，对应人脑的"系统一"。推理模型是"系统二" |
| Jev | 以经济学家杰文斯命名 | 杰文斯悖论：效率提高反而让总消耗上升。暗示智能便宜一百倍，用量涨一万倍 |
| 自回归 | autoregressive | 逐字生成，每个字都要看着前面的字算，像接龙。大模型慢的根源，也是一步走歪后面全歪的根源 |
| 非自回归决策模型 | non-autoregressive decision model | 不接龙，所有选项的概率一次同时算出来，输出的是判断不是文字。思路不新，Jev 是把它做成了产品 |
| 插值 | interpolation | 两个已知刻度之间估中间值，像看温度计。Score 返回 2.76 只能理解为"大概率是 3 档"，不能当成 2 档和 3 档之间的精确读数 |
| 并行采样 | parallel sampler | 一次前向传播算出所有预设槽位的概率 |
| 类型安全 | type-safe | 输出只能是预先定义的类型，格式错误在架构上不可能 |
| 原语 | primitive | Jev 的三种基本问题类型，像编程语言的基本类型一样可组合 |
| Choice | 多选一 | 从一组选项里选一个，返回每个选项的概率 |
| Score | 打分 | 按你定义的等级打分，返回每个等级的概率 |
| Noul | 是否判断 | 一句陈述为真的概率，0 到 1 |
| state | 状态 | 你要它判断的材料，文本或 JSON |
| 置信度 | confidence | 从概率分布的形状算出的单个数字，分布越集中置信度越高 |
| 校准 | calibration | 模型报的概率和真实正确率一致。群体统计，不保证单个答案 |
| RLHF | 人类反馈强化学习 | 训练模型说人爱听的话，产物是聊天模型 |
| RLVR | 可验证奖励强化学习 | 用能自动判对错的任务训练推理，产物是推理模型 |
| RLCD | 校准决策强化学习 | TypeSafe 自创，训练模型输出校准的概率而不是文字 |
| 模式坍缩 | mode collapse | 模型学会只输出某种风格，其他可能被压掉。RLHF 会造成轻度版本 |
| jaggedness | 参差 | TypeSafe 给"已知缺陷"页起的名字，意思是能力边缘参差不齐 |
| context rot | 上下文腐烂 | 无关内容越多准确率越低 |
| 推测性扇出 | speculative fan-out | 一次请求多问，包括可能用不上的问题，反正输出免费 |
| 置信度门控 | confidence gating | 按置信度高低决定自动执行、确认还是转人工 |
| 端到端 | end-to-end | 一个神经网络从最原始的输入直接学到最终输出，中间不人为拆模块。自动驾驶里指从摄像头画面直接出行驶轨迹，感知、预测、规划的活它内部一起学。好处是不确定性不会在模块之间丢失，坏处是黑盒难定位 |
| VLA | 视觉语言动作模型 | 在视觉和动作之间加语言层吸收常识的自动驾驶或机器人模型 |
| 定制输出头 | custom output head | 神经网络最后一层按任务专门设计，智驾的输出头直接出连续轨迹 |
| 隐空间 | latent space | 神经网络内部的中间表示 |
| 最小风险状态 | minimal risk condition | 系统判断搞不定时靠边停车的安全兜底动作 |
| 安全反射层 | safety reflex | 控制回路里高频运行的硬规则，可以否决模型建议 |
